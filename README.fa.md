# هستهٔ نهان

هستهٔ نهان یک سرویس متن‌باز لینوکس، مبتنی بر Xray، برای اتصال به پنل نهان است.

- توسعه‌دهنده و نگهدارنده: **NahaN**
- ایمیل: **nahancode@gmail.com**
- مجوز: **GPL-3.0**؛ منشأ پروژه و مجوز وابستگی‌ها در [NOTICE](NOTICE.md) آمده است.

## وضعیت و امکانات

این نسخه آزمایشی است. قبل از جایگزینی هستهٔ فعال، روی نصب مستقل تست کنید.
خود پنل نهان در این مخزن نیست و باید جداگانه فراهم شود.

امکانات پیاده‌شده شامل دریافت تنظیمات از پنل، تأیید اعمال نسخه، اعتبارسنجی
پروفایل‌ها، نگهداری اسرار روی خود هسته، صف پایدار گزارش ترافیک و تغییر زندهٔ
قوانین اتصال است. تغییر قوانین با تعویض کل تنظیمات یا ارتقای باینری یکسان نیست؛
انتشار تنظیمات می‌تواند موتور را ری‌استارت کند و اتصال‌ها را تحت تأثیر قرار دهد.

مدیریت خودکار GRE، مهاجرت عمومی مشتریان، ارتقای نصب Docker و تمدید خودکار
گواهی‌های واردشده هنوز تضمین نشده‌اند. پشتیبانی موتور از یک پروتکل، لزوماً به
معنی تکمیل مدیریت آن در پنل نیست.

## ارتقای سریع و شناسایی میزبان

برای نصب مستقل systemd، یک بار با باینری رسمیِ دارای امضای معتبر، سرویس موجود
را ثبت کنید. این دستور هستهٔ جدید نمی‌سازد و هستهٔ فعال را ری‌استارت نمی‌کند:

```sh
sudo ./NahaN update register --service YOUR-CORE.service
sudo nahan-core update check
sudo nahan-core update
sudo nahan-core update status
sudo nahan-core update rollback
```

بعد از ثبت، دستور کوتاه `sudo nahan-core update` کافی است. برای چند هسته،
`--core UUID` را اضافه کنید. نسخهٔ برابر دوباره نصب نمی‌شود. ارتقا فقط پس از
تأیید شما انجام می‌شود؛ ری‌استارت هسته ممکن است اتصال‌های فعال را قطع کند.
پنل نسخهٔ جدید را خودکار بررسی می‌کند و ارتقا را تنها پس از دریافت گزارش تازهٔ
باینری اجراشده تأیید می‌کند. آماده‌سازی امضای Ed25519، هش، تنظیمات و revision
پنل را بررسی می‌کند؛ خرابی فعال‌سازی باعث بازگردانی باینری قبلی می‌شود.

باینری مشترک چند سرویس و نصب Docker قابل ثبت نیستند. برای Docker از جایگزینی
بازبینی‌شدهٔ image استفاده کنید؛ بررسی نسخه به معنی امکان ارتقای همهٔ نصب‌ها نیست.

هستهٔ جدید از ایجنت میزبان نسخهٔ ۰٫۴ یا بالاتر، اثبات امضاشدهٔ محلی می‌گیرد؛
پنل پس از اعتبارسنجی، میزبان را خودکار تعیین می‌کند. IP یا نام سرور به‌تنهایی
اثبات هویت میزبان نیست. سرویس غیر root به اتصال محلی محدود و دارای مجوز نیاز
دارد؛ سوکت ایجنت را عمومی نکنید. نبود ایجنت، ارتباط معمول هسته را متوقف نمی‌کند.

## ساخت از سورس

Git و نسخهٔ Go مشخص‌شده در `go.mod` را نصب کنید:

```sh
git clone https://github.com/NahaNCode/nahan-core.git
cd nahan-core
MODFILE=$(go run ./tools/xray-patch)
go test -p 1 -modfile="$MODFILE" ./utility/entryprofile ./utility/controlplane ./api/nahan ./service/controller ./manager
CGO_ENABLED=0 go build -modfile="$MODFILE" -trimpath -ldflags="-s -w" -o NahaN .
```

ابزار patch بخشی از ساخت است؛ دستور سادهٔ `go install ...@latest` جایگزین این
روند نیست. راهنمای [نصب](docs/INSTALLATION.md) شامل تنظیم سرویس systemd و Docker است.

## اتصال از بستهٔ صادرشدهٔ پنل نهان

۱. در مدیریت هسته‌های پنل نهان، هستهٔ جدید را با نام و آدرس سرور ثبت کنید.
۲. «صدور بستهٔ نصب» را انتخاب کنید؛ ویزارد فعلی هستهٔ LAB ثبت می‌کند.
۳. از صفحهٔ بسته، `config.json` و «کلید خصوصی اتصال» (`core.key`) را بگیرید.
۴. هر دو فایل را کنار هم در پوشهٔ اختصاصی هسته قرار دهید. مقدارهای اتصال را
از نمونه‌های قدیمی یا آدرس فرضی جایگزین نکنید.
۵. باینری ساخته‌شدهٔ نهان را از همان پوشه اجرا کنید:

```sh
cd /opt/nahan/runtime
chmod 600 config.json core.key
/opt/nahan/NahaN -c ./config.json
```

۶. در پنل «بررسی گزارش هسته نهان» را بزنید و گزارش تازهٔ هسته را بررسی کنید.
۷. ورودی را در پنل بسازید، بررسی و منتشر کنید و تأیید اعمال آن را از هسته بگیرید.
تست اتصال کلاینت مرحله‌ای جدا از متصل‌شدن هسته است.

فایل صادرشده خودش `CoreID`، آدرس ارتباط و مسیر کلید را دارد. اگر `ServerName`
در بسته آمده، آن را حفظ کنید؛ آدرس IP و نام TLS نباید با هم اشتباه گرفته شوند.
مسیر پیش‌فرض کلید `./core.key` است و نسبت به پوشهٔ اجرای برنامه خوانده می‌شود.

شناسهٔ ورودی‌ها را پنل تعیین می‌کند و هسته خودکار می‌گیرد. نباید `NodeID` یا
کلید API هر ورودی را دستی به بسته اضافه کنید. وصل‌شدن هسته به معنی منتشرشدن
ورودی نیست. ویزارد فعلی فایل اتصال می‌دهد؛ نصب خودکار باینری روی سرور انجام
نمی‌دهد. خود پنل نیز در این مخزن عرضه نمی‌شود.

[راهنمای نصب سرویس](docs/INSTALLATION.md) و [شرح قرارداد مدیریتی](docs/MANAGED-LAB.md)
را ببینید. فایل `examples/managed.json` فقط نمونهٔ ساختار برای توسعه است، نه
جایگزین بستهٔ صادرشدهٔ پنل شما.

رمزها، کلیدها، لینک اشتراک و اطلاعات سرور واقعی را در Git یا issue عمومی
منتشر نکنید. مشکلات امنیتی را خصوصی به ایمیل بالا گزارش دهید.
