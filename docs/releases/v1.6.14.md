# NahaN Core v1.6.14

## Summary

Official-panel management can fall back from public HTTPS to two directly
addressed, privately verified TLS endpoints when the public route is unavailable.

## Changes

- Add bounded public-to-direct failover for core control, native entry reporting
  and the verified updater's panel communication.
- Verify direct endpoints against the embedded public NahaN Control Root and
  the fixed control identity, without trusting IP addresses as identities.
- Prefer a working direct endpoint temporarily and retry public HTTPS after one minute.
- Preserve authenticated payloads and traffic idempotency keys across safe retries.
- Do not replay ambiguous job results, policy receipts or device-lease requests.
- Keep authorization errors, conflicts, redirects and other application responses terminal.
- Preserve the selected SOCKS route during output checks, including direct fallback.
- Add TLS, replay, cancellation, timeout and endpoint-isolation regression tests.

## Compatibility And Upgrade

Automatic fallback applies only to the official panel. Custom endpoints keep
their existing trust and routing configuration. Existing private-control servers
must admit the exact authenticated core APIs before direct fallback is usable.
Both direct IPs currently share a host; this is route resilience, not host-level HA.

Upgrade with the signed catalog, sequentially. A core restart can interrupt
connections. Customer authorization, quotas and forwarding policy are unchanged.
