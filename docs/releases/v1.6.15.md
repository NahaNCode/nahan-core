# NahaN Core v1.6.15

## Engine And Reliability

Updates the embedded Xray engine from 26.7.28 to the reviewed 26.10.21 commit,
including its emergency trust-store update. Upstream labels that engine release
pre-release. Builds pin Go 1.27.3 and the exact engine commit.

SS2022 now uses upstream's native implementation following removal of singbridge.
NahaN's build patches preserve cancellation, reader/writer interruption and timer
cleanup in that implementation. Existing protocol admission and account policies
are unchanged.

## All Changes

- Pin Xray `1b1647cd9ddf0abc34b981d4611fc03bcac1ca74` and required dependencies.
- Pin the reviewed toolchain across Docker, CI and signed release builds.
- Port SS2022 lifecycle cleanup and replace removed bridge-specific fixtures.
- Refresh the engine field catalog with a reproducible source-based generator.
- Adapt upstream error-builder API changes without changing authorization rules.
- Add VLESS RAW, WebSocket and XHTTP real-transfer acceptance tests.
- Add independent legacy SS2022 TCP/UDP compatibility tests for all three methods.
- Add a bounded CLI resource/retained-stream comparison harness.
- Preserve detection rules in last-good snapshots; reject incomplete offline
  restoration instead of panicking or silently dropping enforcement rules.
- Require runtime tests and public-source checks before signed release builds.

## Upgrade Notes

Deploy backend receipt compatibility for engine versions 26.7.28 and 26.10.21
before updating managed cores. Catalog regeneration does not automatically enable
new protocol fields in the panel. Update one canary first and verify real traffic,
configuration acknowledgements and usage reporting before continuing the fleet.

The updater restarts the selected core; existing connections may be interrupted.
Keep the previous verified binary and runtime checkpoint available for rollback.
