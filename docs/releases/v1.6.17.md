# NahaN Core v1.6.17

## Summary

Improves service-level rate enforcement and makes distributed admission failures
distinguishable from explicit authorization denial. Embedded Xray remains
26.10.21; existing client credentials and endpoints are preserved.

## All Changes

- Keep one service rate bucket across authorized inbounds, shared credentials
  and individually registered devices.
- Apply newly introduced speed limits to already-established, previously
  unlimited streams without requiring reconnects.
- Recompute the minimum applicable inbound ceiling on configuration changes;
  a faster assignment can no longer raise a stricter shared ceiling.
- Replace legacy cached-map IP coordination with atomic Redis Lua admission,
  canonical IP identities, individual presence expiry and scoped service keys.
- Bound Redis connections, request time, presence cardinality and renewal work;
  support TLS with normal certificate verification and explicit outage policy.
- Add backend-controlled, opt-in native IP leases over the authenticated control
  API, with bounded singleflight admission and batched renewal.
- Separate coordinator unavailability from explicit device/IP denial; an outage
  neither invents a grant nor prematurely revokes an unexpired grant.
- Bound registered-device request concurrency and total renewal time, rotating
  the batch order to avoid permanent starvation.
- Add real Redis/PostgreSQL integration, multi-runtime VLESS admission, live rate
  change and concurrency regression coverage.

## Deployment Notes

Native atomic-IP coordination is disabled unless an operator explicitly enables
compatible node IDs in the backend. This release does not automatically change
customer IP/device policy or enable a new offline cutoff. When enabled, native
IP grants last at most 120 seconds; prolonged coordinator failure can prevent
traffic after expiry. The standalone legacy adapter has a separate documented
allow/deny outage policy.

Dynamic multi-core speed allocation with epoch fencing is not part of this
release. Existing backend rate division remains in place. Admission diagnostic
getters do not yet constitute a complete admin monitoring workflow.
